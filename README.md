# StoryCast

StoryCast is a three-page, accessible microsite for audio and video storytelling. Every story ships with captions and a full transcript. It is built with semantic HTML5, Sass, CSS Grid and Flexbox, and a little vanilla JavaScript. No frameworks.

- **Home** (`index.html`): introduces StoryCast and features three stories.
- **Story detail** (`story/*.html`): player, captions, synchronised transcript and related stories. Three sample stories share one template.
- **About & Access** (`about.html`): mission, accessibility features, how to engage, accessibility statement.

> **About the sample media.** The three stories are fictional samples written for this project. Their narration is **computer-generated** (eSpeak NG), so it sounds robotic and every character has a similar voice. It was used so that the captions and transcripts are genuinely time-aligned to the audio. The video visuals are abstract placeholders. Replace the files in `assets/` to publish your own.

### What the supporting files do

| File or folder | Purpose | Needed to run the site? |
| --- | --- | --- |
| `js/main.js` | About 90 lines of vanilla JavaScript, loaded only on story pages. It turns transcript timestamps into buttons that seek the media, highlights the line being spoken (`aria-current`), shows live captions under audio players, and adds the playback-speed menu and follow-along scrolling. Everything important works without it. | No (progressive enhancement) |
| `package.json`, `package-lock.json` | Define the one dependency (Sass) and the `npm run` commands. The lock file pins exact versions so `npm install` gives everyone the same setup. | Only to rebuild the CSS and use `npm run serve` |

## Run it locally

You need [Node.js](https://nodejs.org/) 18 or newer (only for compiling Sass and running a static server).

```bash
git clone https://github.com/Nnamdi004/storycast.git
cd storycast
npm install          # installs Sass
npm run build        # compiles sass/main.scss -> css/main.css
npm run serve        # serves the site at http://localhost:8000
```

Open <http://localhost:8000>. `css/main.css` is already compiled and committed, so you can also open `index.html` directly, but use a local server to test media seeking properly.

> **Use a server that supports HTTP range requests** (`npm run serve` does). Python's `python3 -m http.server` does not, so clicking a transcript timestamp will not seek the audio or video.

| Command | What it does |
| --- | --- |
| `npm run build` | Compile Sass once |
| `npm run watch` | Recompile Sass on every change |
| `npm run serve` | Static server with range-request support |

## Accessibility checklist

Target: **WCAG 2.1 level AA**.

| Requirement | How it is met |
| --- | --- |
| Transcripts or captions for all audio/video (1.2.1, 1.2.2) | Every story has a time-stamped transcript on the page (also downloadable as `.txt`). Video uses `<track kind="captions" default>`; audio stories also show a live caption line under the player. Caption files live in `assets/captions/`. |
| Audio description or media alternative (1.2.3, 1.2.5) | The sample video's visuals are decorative; a text description sits in a `<details>` element linked with `aria-describedby`. Real footage would need audio description. |
| Semantic structure (1.3.1, 2.4.6) | `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<aside>`, `<figure>`/`<figcaption>`, `<footer>`. One `<h1>` per page and no skipped heading levels. |
| Page language and titles (3.1.1, 2.4.2) | `lang="en"` on `<html>`; unique, descriptive `<title>` per page. |
| Skip link and landmarks (2.4.1) | A "Skip to main content" link is the first tab stop on every page. `<nav>` elements are labelled (`Main`, `Breadcrumb`, `Footer`). |
| Keyboard operable (2.1.1, 2.1.2) | Native `<audio>`/`<video>` controls, buttons and links only. No keyboard traps. The scrollable transcript is focusable (`tabindex="0"`) with a name. |
| Visible focus (2.4.7) | 3px offset outline on every focusable element; colour swaps to amber on dark surfaces. Focus ring on a media card wraps the whole card. |
| Contrast (1.4.3, 1.4.11) | Text >= 4.5:1, UI borders and focus rings >= 3:1. All 24 colour pairings were checked. |
| Not colour alone (1.4.1) | Media type is a word badge ("Audio"/"Video"). Current page is shown with an underline. Active transcript line uses a tint plus a thick bar plus `aria-current`. |
| Reflow and resize (1.4.4, 1.4.10) | rem-based type, fluid layout, no horizontal scroll down to 320px wide. |
| Text spacing (1.4.12) | No fixed heights on text containers; line height 1.65. |
| Target size (comfort) | Buttons and links have a 44px minimum block size; transcript timestamps are 36px. |
| No autoplay, user control (1.4.2, 2.2.2) | Nothing plays automatically. Playback speed is adjustable. Animation and smooth scroll stop under `prefers-reduced-motion`. |
| Names, roles, values (4.1.2) | Native elements first. ARIA used only where needed: `aria-label` on players and timestamp buttons, `aria-current` on nav and the active transcript line, `aria-labelledby` on sections and the transcript region, `aria-hidden` on decorative SVG and the live-caption mirror. |
| Images (1.1.1) | Decorative images use `alt=""`; story cover art on the detail page has descriptive alt text. |
| Works without JavaScript | Players, captions, transcripts and navigation all work with scripting off. JS only adds clickable timestamps, live captions for audio, follow-along scrolling and speed control. |

### What was tested

- Colour contrast check: 24 of 24 pairings pass.
- axe-core 4 (WCAG 2.0/2.1 A and AA plus best-practice rules) on all five pages at 1280px and 390px: 0 violations.
- Headless Chromium: no horizontal scrolling at 320px width on any page; tab order checked on Home; container-query layouts confirmed.
- Static checks: every local `href`/`src` resolves, every `<img>` has an `alt`, one `<h1>` per page.

## Container query component

`.media-card` (see `sass/_components.scss`) declares `container: media-card / inline-size` and changes layout based on the width of the box it sits in, not the viewport:

- narrow container (about 22rem or less): stacked card with a short thumbnail
- 32rem and up: image beside text
- 52rem and up: larger heading and text (the featured slot)

The transcript also uses a container query to place timestamps in their own column once it is 30rem wide.

## Add or replace a story

1. Put the media in `assets/audio/` or `assets/video/`, captions in `assets/captions/` (WebVTT) and a text transcript in `assets/transcripts/`.
2. Copy an existing page from `story/` and update the title, media paths, transcript cues and related stories.
3. Add a card for it on `index.html`.

## Design files (Figma)

The wireframes and high-fidelity mockups are linked in the Deliverables table. To rebuild or edit them:

1. Create a Figma design file and drag the SVGs from `docs/wireframes/` onto the canvas; they import as editable shapes and text.
2. Build the mockups at 1280px (desktop) and 390px (mobile) using the built pages in `docs/screens/` as a reference.
3. Use the tokens in `sass/_colors.scss` (brand `#2a2c6e`, night `#181a45`, clay `#a8381b`, accent `#ffb703`, paper `#fbf8f3`, sand `#f1e9dd`) and the Inter typeface for text.
